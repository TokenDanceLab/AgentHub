- OIDC JWT generation, authentication, session management, and message send/receive all work end-to-end.
- Content normalization (text -> jsonb `{"text": "..."}`) works correctly.
- Friend requirement is enforced for private session creation.

**Edge API surface: WORKING**
- Run creation, status polling, listing, agent/runner discovery all function correctly.
- The API returns proper structured responses with error codes.

**Edge actual execution: NOT FULLY FUNCTIONAL**
- The Claude Code adapter appears registered and the runner reports online, but runs either fail instantly or complete without producing expected artifacts.
- This is likely an environment/configuration issue (model access, CLI invocation, or workDir permissions) rather than an API routing problem.
- The `/v1/runs/{id}/output` and `/v1/runs/{id}/events` REST endpoints do not exist; events are WebSocket-only at `/v1/events`.

**Web/Desktop connectivity: FULLY WORKING**
- Both Vite dev servers serve the React app correctly on ports 5174 (Web) and 5173 (Desktop).

## Issues Found

1. **client_msg_id must be UUID**: The `POST /client/sessions/{id}/messages` endpoint rejects non-UUID `client_msg_id` values with a generic `BAD_REQUEST`. The API documentation or error message should clarify this requirement.

2. **Edge run execution gap**: The Edge server's Claude Code adapter needs investigation into why runs fail instantly or complete without artifacts. Likely needs:
   - Verification that the `claude` CLI can be invoked by the Edge process
   - Check of model access / API key configuration
   - Review of workDir allowlist configuration
