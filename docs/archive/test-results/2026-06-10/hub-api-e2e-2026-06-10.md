## Bugs Found

### BUG-1: Logout 500 (MEDIUM)
- **Endpoint:** `POST /client/auth/logout`
- **Error:** `INTERNAL_ERROR` (500)
- **Cause:** Manually-generated JWT has no refresh token in the database. Logout tries to revoke a non-existent session/refresh token and fails.
- **Impact:** Users who have no valid refresh token will get a 500 on logout instead of graceful handling.
- **Fix:** Logout should be idempotent — if no refresh token exists, return 200.

### BUG-2: Message Reactions 500 (HIGH)
- **Endpoint:** `POST /client/messages/:id/reactions`
- **Error:** `INTERNAL_ERROR` (500)
- **Cause:** Database column name mismatch. The `message_reactions` table has an `emoji` column (text), but the GORM model `MessageReaction.Reaction` maps to a column named `reaction` (varchar). GORM cannot find the `reaction` column and returns an error.
- **Impact:** Message reactions are completely broken — users cannot add or remove reactions.
- **Fix:** Either rename the DB column from `emoji` to `reaction` via migration, or add a GORM column tag `gorm:"column:emoji"` to the model's `Reaction` field.

### BUG-3: Private Session Create 400 (LOW)
- **Endpoint:** `POST /client/sessions/private`
- **Body:** `{"target_user_id": "..."}`
- **Error:** `BAD_REQUEST` (400)
- **Cause:** Likely a request binding issue — may need different field names or self-session is rejected.
- **Impact:** Cannot create private sessions via this endpoint for the only existing user.

## Auth Notes

JWT tokens must include:
- `user_id`: UUID of an existing user
- `device_type`: `web` for `/web/*` routes, `desktop` for `/edge/*` routes
- `device_id`: device identifier string
- `iss`: `agenthub-hub`
- `aud`: `agenthub-api`
- `sub`: same as `user_id`
- Standard `iat`/`exp` claims

The `device_type` field is enforced by `DeviceTypeCheck` middleware on `/web/*` (requires `web`) and `/edge/*` (requires `desktop`).
